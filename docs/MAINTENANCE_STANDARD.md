# Maintenance Standard

Threeell Studio's managed service exists to keep the client's website healthy and current without requiring the client to manage the technical system.

## Routine Responsibilities
Depending on the project:
- Site availability checks
- Dependency/plugin/core updates
- Backup verification
- Security review
- Form checks
- Broken-link checks
- Performance checks
- Small content changes
- Basic analytics review
- Deployment/release management

## Request Classification

### Small Content Change
Examples:
- Replace supplied image
- Correct text
- Update contact details
- Change opening hours
- Update a small existing content block

### Maintenance Fix
Repair of existing agreed functionality.

### Enhancement
Adds meaningful capability or structural change.

Examples:
- New major page type
- New integration
- New interactive section
- New CMS workflow

### New Project
A change large enough to require separate discovery, architecture, design, or commercial scope.

## Protection Against Scope Creep
Monthly management must never be interpreted as unlimited design/development.

The commercial agreement should define:
- Included edit allowance or fair-use boundary
- Support channel
- Expected response window
- What constitutes emergency work
- What is separately billable

## Security Rule
Never store passwords, API keys, tokens, database credentials, private keys, or client secrets inside repositories or normal documentation.

## Continuity Rule
A maintained project must have enough documentation that it can be safely updated without reverse-engineering the entire build.
